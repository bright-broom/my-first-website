# Yuka — 柴谷由佳

**People. Possibilities. — 人の強みを見つけ、次の可能性につなげる。**

柴谷由佳（Yuka）の経験・強み・価値観を紹介する、1ページの公開プロフィールです。
アイボリーとブルー、大きなタイポグラフィ、オリジナルの軌道グラフィックで、人の可能性と、領域を越えた経験を表現しています。

## まず動かす

必要なものはGit、Python 3、ブラウザです。Node.js、パッケージのインストール、ビルドは不要です。

```sh
git clone https://github.com/shibanyan06-source/my-first-website.git
cd my-first-website
python3 -m http.server 8765 --bind 127.0.0.1
```

[ローカルプレビュー](http://127.0.0.1:8765/)を開いてください。終了は `Ctrl+C`。
すでにクローン済みの場合は、そのフォルダで最後のコマンドだけを実行します。
ポートが使用中なら `8766` などに変更し、開くURLのポートも合わせてください。

`index.html` を直接開いても表示できますが、確認時はHTTP配信を使用します。
このサーバーはローカル確認用です。本番の配信サーバーとしては使いません。

## 構成と現在の機能

```text
.
├── index.html   # ページ構造、文章、メタ情報、インラインSVG
├── style.css    # デザイントークン、レイアウト、レスポンシブ対応
└── README.md    # 開発・検証・公開の入口
```

| セクション | 役割 | 移動先 |
| --- | --- | --- |
| Hero | コンセプトとグラフィック | `#top` |
| About | サイトの背景・自己紹介 | `#about` |
| Experience | 小売・デジタル分析・インフルエンサーマーケティングの経験 | `#explore` |
| Values | 加点の視点・気持ちの準備・身軽さ | `#values` |
| Contact | 今後の更新案内・連絡先の準備状況 | `#contact` |

ナビゲーション、本文へのスキップリンク、トップへ戻るリンクを備えています。
**Contactは案内表示のみで、メール送信やフォーム受付の機能はありません。**
認証・データ保存・アクセス解析も実装していません。

## 設計方針

### HTML/CSSで完結させる

現在の要件は文章とグラフィックの表示、ページ内移動です。
標準HTML/CSSで実現できるため、JavaScript、フレームワーク、UIライブラリ、ビルド工程は導入していません。
更新箇所と運用負担を少なく保ち、フォーム送信や複数ページの共通化など、具体的な要件が生じた時点で構成を見直します。

### デザインの責任を明確にする

| 要素 | 方針・編集箇所 |
| --- | --- |
| 色・幅・左右余白 | `style.css` の `:root` に集約 |
| 日本語フォント | Noto Sans JPを優先。未インストール環境ではOSの日本語フォントにフォールバック |
| 欧文見出し | ArialとGeorgiaの組み合わせ |
| グラフィック | `index.html` 内のオリジナルSVG。球体、軌道、背景のグリッド |
| レスポンシブ | 基本レイアウトに加え、1000px以下・640px以下・1600px以上で調整 |
| 動き | ホバーとページ内の滑らかな移動。`prefers-reduced-motion: reduce` で無効化 |

外部フォント、画像CDN、第三者スクリプトへの通信はありません。
フォントは端末依存のため、環境によって字形と改行位置が変わります。

2026-09-28のデザイン改訂では、共通フロントエンドガイドとカタログ（2026-09-14、版1.0）を参照しました。
採用範囲はこの1ページの標準HTML/CSSと独自SVGです。外部部品・素材の追加はありません。
このREADMEにプロジェクト固有の方針を残しており、開発者のローカルガイドがない環境でも編集できます。

## 更新するとき

| 変更したいもの | 編集する場所・注意点 |
| --- | --- |
| タイトル・検索向け説明 | `index.html` の `title` と `meta[name="description"]` |
| 各セクションの文章 | `index.html` の対応する `section` |
| ナビゲーション | リンクの `href` とセクションの `id` を対応させる |
| 配色・全体幅 | `style.css` の `:root`。色を変えたら本文とフォーカスの視認性も確認 |
| 見出し・余白 | 通常ルールと末尾のメディアクエリ。特定幅だけの上書きにも注意 |
| グラフィック | `.hero-art` 内のSVG。内容が変わったらコンテナの `aria-label` も更新 |
| 問い合わせ先 | `.contact-status`。公開用の連絡先が確定したら有効なリンクへ変更 |

実績・連絡先は確認できた情報だけを掲載します。
連絡先やフォームを追加する際は、実際に届くことまで確認し、見た目だけで受付完了を示さないようにします。

## 変更の確認方法

自動テスト、lint、CIは現時点ではリポジトリにありません。以下を手動で確認し、結果をPRに残します。

1. ローカルサーバーで表示し、開発者ツールでコンソールエラーとリソースの読込失敗を確認する。
2. 320 / 375 / 768 / 1024 / 1440 CSS pxで、横スクロール、文字切れ、重なり、意図しない改行を確認する。
3. `Tab` で「本文へ移動」を表示し、`Enter` で本文にフォーカスが移ることを確認する。その他のリンクにも見えるフォーカスがあることを確認する。
4. About / Experience / Contact / Back to topの移動先を確認する。
5. ブラウザのズーム200%と、OSまたは開発者ツールの「動きを減らす」設定でも操作できることを確認する。
6. `git diff --check` で差分の空白エラーを確認する。

## 公開と今後の優先事項

配信に必要なのは `index.html` と `style.css` です。同じ階層を保って静的ホスティングへ配置します。
公開用URL・配信先設定・自動デプロイは、このリポジトリ内のファイルからは確認できません。
**PRのマージと本番への反映は別の工程です。**

| 優先 | 作業 | 完了の目安 |
| --- | --- | --- |
| 1 | 所有者が公開先・URL・配信方法を決める | 公開URLでHTML/CSSが正常に読み込まれる |
| 2 | 公開環境で表示・操作を確認する | 主要リンク、実機、Safari、文字拡大、動きを減らす設定の結果を記録 |
| 3 | 連絡先の掲載方針を決める | 準備中表示を続けるか、有効な公開連絡先を掲載するかが確定 |
| 4 | 更新頻度に応じて自動検証を追加する | 再発を防ぎたい不具合に対する、再実行可能な検証がある |

公開後の修正もブランチとPRで管理し、変更内容・確認結果・未確認事項を残してください。
